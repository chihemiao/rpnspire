# 3.0 迁移计划与里程碑

> 状态：设计稿，未开始实现。

## 1. 策略：并行新建，逐个主题搬迁，2.x 继续可用

不在 2.x 上原地大改，也不一次性全部重写后才能用：

1. 新代码放在 `v3/`（目录见 [架构设计 §4](02-architecture.md)），有自己的入口和构建目标（先叫 `vce3.tns` / `vce3_zh.tns`，只给测试用）。
2. 2.x 保持可发布：只修 bug（版本 2.4.x），不再加功能。
3. 每个主题按同一流程搬迁（§3），用 2.x 的结果做对照测试。
4. 全部主题搬完、新功能（逐答案步骤、作图工作台、向量工作台）达到 P1，并通过真机验证后，`vce.tns` / `vce_zh.tns` / `rpn.tns` 的入口切到 3.0，删除 2.x 代码。
5. 3.0 第一次打开 2.x 的文档时，自动升级保存的历史题目（[架构设计 §9](02-architecture.md)）。

可以直接复用的 2.x 模块见 [架构设计 §12](02-architecture.md)。

顺序的理由：

- 风险最大的平台问题先验证（M0）。
- 骨架用最简单的主题打通（M1）。
- 录制回放尽早上线（M2），后面每个主题都受益。
- 用户最想要的作图和向量排在其他主题前面（M3、M5）。

### 2.1 M0 要在真机上回答的问题

| 问题 | 怎么测 | 如果答案是“不行” |
|---|---|---|
| coroutine 里能不能调用 `math.evalStr` | 一个小脚本：在 `coroutine.wrap` 里调用并 yield | 任务改为同步执行（接口不变，失去分段和取消） |
| `timer.start` 最小间隔、在 `on.timer` 里继续 coroutine 是否稳定 | 计数 1 秒内的 tick 数 | 用按键事件推进任务 |
| 单次 `math.evalStr` 的典型耗时（简单化简、solve、integral、limit） | 每种 20 次取平均 | 调整预算和缓存策略 |
| Lua 堆能用多少 | 逐步分配直到报错，记录 `collectgarbage('count')` | 定下缓存（mathbox、采样、FactGraph）的上限 |
| 脚本体积上限 | 用填充代码生成 300/500/800 KB 的文档，看能否打开 | 拆分功能、release 构建去注释和压缩标识符 |

| `var.store` 能存多长的字符串 | 逐步加长 | 导出分块 |
| `debug.traceback` 是否可用 | 直接调用 | 只记录错误消息 |
| 能否读取当前求值设置（`math.getEvalSettings`） | 直接调用并打印 | 在 rpnspire 里打开工具箱时提示会改动设置 |
| apiLevel 2.7（如果 OS 支持）带来哪些可用的 API | 查文档并在真机上试 | 继续 2.4 |

## 3. 每个主题的搬迁流程

1. **固定 2.x 的行为**：用 2.x 跑这个主题的所有自检用例和测试输入，导出每个答案的数值，存成对照数据（`tests/parity/<主题>.lua`）。
2. **拆出数学**：把 2.x 解题器里的数学搬到 `mathx/`，变成纯函数（输入领域对象，输出结论）。顺手合并重复的工具函数（清单见[现有功能总结](01-current-features.md)的“重复代码”）。
3. **写主题**：`schema`（有类型的输入框）、`solve`（写 FactGraph，每个结论带步骤和依赖）、`present`、`examples`、`cases`。
4. **测试**：对照测试（数值一致）、金样测试（结论和步骤）、步骤覆盖测试（每个主答案都有步骤）、界面测试（按 key）。
5. **翻译**：消息 id 和中文。
6. **保存升级**：2.x 这个主题的字段映射到 3.0，并加升级测试。
7. **录制**：在 TI 电脑版软件里跑这个主题的用例，录 CAS 夹具。

## 4. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 3.0 体积超过真机能打开的上限 | 无法发布 | M0 先测上限；CI 体积预算；release 构建裁剪调试代码 |
| coroutine/timer 在真机上不能用于 CAS 调用 | 长计算仍会冻结界面 | 退回同步执行；保留“离开输入框再算”和编辑时占位 |
| 真 CAS 的返回格式和 mock 不同 | 真机上出错 | 录制回放（M2）+ 契约测试 + 发布前真机自检 |
| 搬迁时丢功能 | 用户发现旧功能没了 | 对照测试 + 现有功能清单逐条打勾 |
| enter 的含义变了（精确/小数 → 展开步骤） | 老用户不习惯 | 提示栏说明；设置里可以切回旧行为；更新说明里写清楚 |
| 范围太大 | 迟迟不能发布 | 严格按 P1/P2/P3；M3 完成后就可以发 3.0 beta 给自己用 |

## 5. 迁移期间 2.x 要修的已知问题

阅读代码时发现的 2.x 问题。第 1 条已经在桌面测试环境（mock CAS）里复现，真机上还没有试过：

1. **输入框里没提交的文字可能丢失或被旧内容覆盖。** `set_rows` 会先提交编辑，这会调用 `on_commit`，`on_commit` 可能调用 `refresh_problem`，后者又调用 `set_rows`；外层的 `set_rows` 随后装入它在提交之前建好的旧行。这在框里还有未提交文字时选菜单（全部改为小数、改小数位数或字号）会发生。桌面复现：在正态分布的事件框里输入 `X<55` 不离开，选“小数位数 3”，题目里已经有 `X<55`，但输入框显示为空。如果菜单先切换了屏幕（例如回到首页），`on_commit` 直接返回，打的字没有写进题目（桌面复现：输入后选 Home，事件框的内容丢失）。3.0 用“意图先提交编辑、再改状态”的顺序从结构上避免；2.x 可以在 `refresh_problem` 和切换屏幕之前先同步提交编辑框。
2. **精确/小数选择没有保存。** `p.modes` 不在 `History.save` 里，重新打开文档后恢复成默认。
3. **“全部改为小数”会改掉设置里的默认模式**，而不只是当前题目。
4. **网站部署不等 Lua 测试**：`site.yml` 不跑 Lua 测试也不依赖 `test.yml`，测试失败时网站照样部署。
5. **反馈表的 IP 哈希可能没有加盐**：仓库和部署流程里都没有设置 `IP_SALT`（`site/src/worker.mjs` 第 96 行）。除非在 Cloudflare 控制台里手动设过，代码会退回到写在源码里的固定字符串，IP 哈希可以被逐个 IP 试出来。应该在 Cloudflare 里设置一个随机的 `IP_SALT` 密钥。

## 6. 需要你决定的事

| 问题 | 建议 |
|---|---|
| “平面/线与一个点的最远距离”：点到无限的平面或直线没有最远距离，是否指最短（垂直）距离？ | 按最短距离设计（同时给出垂足和对称点）；如果你指的是别的（例如线段或有界区域），请说明 |
| enter 改为展开步骤，精确/小数改为 ◀▶，可以吗？ | 可以，并保留设置开关 |
| “离开输入框再算”是所有主题都用，还是只给慢的主题？ | 只给慢的主题（作图、面积体积、微分方程、参数、变换、运动学、向量）；概率保持输入就出答案 |
| 作图工作台最多几个函数？ | 6 个（颜色和屏幕的限制） |
| 向量工作台里，不确定是否在考试范围内的问题（异面直线距离等）要不要做？ | 做，但放在“更多”里，默认不显示 |
| Beta 期间网站上同时提供 2.x 下载吗？ | 提供，标为“稳定版” |
